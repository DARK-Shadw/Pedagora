# Database

## Overview

Pedagora uses **Supabase** (hosted PostgreSQL) with Row Level Security (RLS). The schema is defined via SQL migration files in `supabase/migrations/`.

## Migrations

| File | Description |
|---|---|
| `00001_initial_schema.sql` | All tables, ENUMs, indexes, RLS policies, and triggers |
| `00002_add_preference_notes.sql` | Adds 5 `*_note TEXT` columns to `user_preferences` |

Migrations are run manually via the Supabase SQL editor (not via CLI in this project).

### Migration Naming Convention

```
NNNNN_description.sql
```

Sequential 5-digit numbers. New migrations should increment from the last one.

## RLS (Row Level Security)

All tables have RLS enabled. The general policy pattern:

```sql
-- Users can only read their own data
CREATE POLICY "Users can view own data" ON table_name
  FOR SELECT USING (auth.uid() = user_id);

-- Users can only insert their own data
CREATE POLICY "Users can insert own data" ON table_name
  FOR INSERT WITH CHECK (auth.uid() = user_id);

-- Users can only update their own data
CREATE POLICY "Users can update own data" ON table_name
  FOR UPDATE USING (auth.uid() = user_id);
```

This means even if the client-side code is compromised, a user can never access another user's data.
